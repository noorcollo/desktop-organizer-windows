# Security policy

## Supported versions

Security fixes are applied to the latest published release and the current default branch. Older releases may not receive updates.

## Reporting a vulnerability

Please do not open a public issue for a suspected security vulnerability. Contact the repository owner privately through the GitHub profile associated with this project and include a clear description, affected version or commit, reproduction steps, and the minimum evidence needed to validate the report.

Never send passwords, access tokens, private documents, complete personal configuration files, or unredacted screenshots. Replace usernames, personal paths, and document names with placeholders.

The project owner will acknowledge a valid report, investigate it, and coordinate a fix or mitigation before public disclosure where appropriate. Reports that concern only a local file-movement mistake should normally be opened as a regular bug report after removing private information.
